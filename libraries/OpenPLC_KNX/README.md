# OpenPLC_KNX

中文：[README.zh-CN.md](README.zh-CN.md)

KNX for the OpenPLC board: group objects and DPT encoding from the
[thelsing/knx](https://github.com/thelsing/knx) stack, carried over KNXnet/IP
(Ethernet) and over the KNX TP bus (terminals C03 / C04, STKNX transceiver).

## Roles

The sketch picks the stack's mask version with one line near its top, written
like `OPENPLC_APP_VERSION`:

```cpp
OPENPLC_KNX_ROLE(TP_DEVICE);   // or OPENPLC_KNX_ROLE(IP_ROUTER);
```

| Role | Line | Mask | Transports |
|---|---|---|---|
| KNX TP device | `OPENPLC_KNX_ROLE(TP_DEVICE);` | `0x07B0` | TP; group objects that ETS links to group addresses |
| KNX IP router | `OPENPLC_KNX_ROLE(IP_ROUTER);` | `0x091A` | routes between KNXnet/IP and TP, no group objects |

It must be in the `.ino` file, on a line of its own. A sketch that uses this
library without it does not compile, and the error names the line to add.
There is no KNX role in the Tools menu.

Both are masks ETS knows, so ETS can program the board in either role.
What ETS downloaded survives sketch uploads as long as the role stays the same. After a role change,
or on a board programmed with an earlier board package, the board discards that data at start-up
(log: `ETS has to reprogram PA and application!`) and runs unprogrammed until ETS downloads it again.
Import the ETS product file `OpenPLC_TP.knxprod` from [OpenPLC_ETS_Prod](https://github.com/haliboteda/OpenPLC_ETS_Prod) first.

| Example | Role | Shows |
|---|---|---|
| `KNX_Switch` | TP device | the six relays as a switch actuator, programmed by ETS |
| `KNX_Inputs` | TP device | the eight digital inputs as a binary input, programmed by ETS |
| `KNX_Temperature` | TP device | takes a sensor's temperature and, above a threshold set from the Serial Monitor (default 27 C), switches another device and DO2; programmed by ETS |
| `KNX_Analog` | TP device | sends AI1 / AI2 as 2-byte float values and sets AO1 / AO2 from values written on the bus, programmed by ETS |
| `KNX_BusMonitor` | TP device | prints every telegram on the bus; sends group writes typed in the Serial Monitor. No ETS needed |
| `KNX_IPRouter` | IP router | passes telegrams between TP and KNXnet/IP |

The examples print with `Serial`: read them in the Serial Monitor on the
board's USB port. `Serial` is USB port 1 (also `SerialUSB`). The examples
never wait for the PC: their opening lines (the KNX address) are printed each
time the Serial Monitor connects, so after a reset reopen the monitor to see
them.

| Object | Port |
|---|---|
| `Serial` / `SerialUSB` | USB port 1 (the board's USB connector) |
| `RS232` | terminals C05 / C06, real RS232 levels; opened by `RS232.begin()` |
| `RS485` | terminals C10 (A) / C11 (B) |

## The `KNX` object

A sketch uses one object, `KNX`:

| Method | Does |
|---|---|
| `setup(orderNumber = "OPENPLC-TP", manufacturerId = 0x00FA)` | Once in `setup()`: board pins, programming button and LED, loads what ETS downloaded |
| `start()` | Starts the stack; call after setting group-object callbacks |
| `loop()` | Every `loop()` |
| `progMode()` | In ETS programming mode |
| `configured()` | ETS has downloaded an application |
| `individualAddress()` | This board's individual address |
| `getGroupObject(n)` | Group object `n` of the ETS product, a `GroupObject&` (TP device only) |
| `onBusFrame(cb)` | Every good frame on the TP bus goes to `cb`, whoever it is for (`KNX_BusMonitor`) |
| `sendGroupWrite(ga, value)` / `sendGroupWrite(ga, data, len)` | A GroupValue.Write straight onto the TP bus, no ETS needed: a 0..63 value, or 1..14 data octets |
| `onBusSendDone(cb)` | `cb(ok)` after each `sendGroupWrite`; `ok` = acknowledged |

Object numbers (`KNX_OBJ_RELAY1_SWITCH` …) and `OPENPLC_KNX_ORDER_NUMBER` come from `src/openplc_knx_objects.h`, which `OpenPLC_KNX.h` includes. It is generated by `OpenPLC_ETS_Prod/tools/gen_product.py` from `knx_objects.json`: edit the JSON, not the header.

## The TP bus

The STKNX is a bare TP1 transceiver, not a TP-UART: the library makes the bits
itself. TIM12 channel 1 puts each logical 0 on `KNX_TX` (PB14) as a 35 µs pulse
in a 104 µs bit period, and TIM1 channel 3 timestamps every pulse on `KNX_RX`
(PA10). Characters, frames, the acknowledge 15 bit times after a frame,
repetitions and collision handling all run inside those two timer interrupts,
so a slow `loop()` does not make the board miss an acknowledge.

**Using this library reserves TIM1 and TIM12.** Do not use them for PWM or
anything else in the same sketch.

`KNX.setup()` drives PB14 low first thing, whatever the role: a floating
PB14 makes the transceiver draw current from the bus.

## Board facts the examples rely on

| Signal | Pin | Note |
|---|---|---|
| Programming button | PG9 | Pressed = high (external 10k pull-down). Same net as BOOT0 — the library only reads it. Press once while the sketch runs to toggle programming mode; **do not hold it while powering up or resetting**, which enters the bootloader's upload mode |
| Programming-mode indicator | PE2 | The system LED: on while in programming mode, and the system log gets `[sys][KNX] programming mode on` / `off`. A sketch using this library leaves the system LED to it. (The schematic's `KNX_Prog_LED` line, PG11, has no LED fitted.) |
| Bus voltage present | PH12 | High when the bus powers the transceiver |
| `KNX_OK` | PD7 | Reads low on this board whatever the bus does; do not use it to detect the bus |

When ETS tells the board to restart (for example during a download), the
library writes one line to the system log just before the reset, so the log
shows who caused it: `[sys][KNX] restart requested by ETS (basic)` or
`[sys][KNX] restart requested by ETS (master reset, erase code N)`. The system
log is kept across the reset and comes out on USB port 1 (`Serial`) once a
terminal opens it.

## The KNX stack

`src/knx/` is a copy of thelsing/knx with RF and the editor-only `#pragma region` markers removed. It keeps the ETS data in a
16 KiB block at the start of flash sector 6 (`KNX_FLASH_SIZE`, set by the board
package for every role). Its own debug output is off; build with `-DKNX_DEBUG`
to send it to the system log as `[sys][KNX]` lines.
